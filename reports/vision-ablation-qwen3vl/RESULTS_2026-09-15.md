# Can current Qwen3-VL replace the complete DealSynq extraction pipeline?

Development benchmark, 15 September 2026. [Image-only run and raw outputs](../../benchmarks/qwen3vl-vision-only-coulton-20260915-r3/README.md) | [Complete pipeline run](../../examples/coulton-creek-v070-full-qwen-audited-r1/README.md) | [Machine-readable score](../../benchmarks/qwen3vl-vision-only-coulton-20260915-r3/score.json) | [Brief PDF](../../output/pdf/dealsynq_qwen3vl_vision_only_vs_full_pipeline_2026-09-15.pdf)

## Answer to Rahul

Rahul's question in the 14 September meeting was whether a vision model could replace or simplify the deterministic OpenCV/OCR work for extraction, particularly tables, charts and maps, and whether it could deliver the agreed step-one structured output efficiently. That is a good question, and the older Qwen3.5 ablation could not answer it for **Qwen3-VL**.

The new test is **mixed, not a simple win for the complete pipeline**. On 65 visibly checked content/ownership anchors across eight difficult pages of the same PDF, current Qwen3-VL image-only scored **56/65 (86.2%)**, while the published full pipeline scored **50/65 (76.9%)**. In this development set, Qwen alone is plainly better on the two KPI clusters (page 3), four of five paired labels in the nested pies (page 9), and the legal column order (page 16). The complete pipeline is plainly better on map-state/value ownership (page 8), blank-sensitive loan-table columns (page 6), and delivering durable Unified Source Blocks with page inspection, coordinates and verified evidence files. Both recover simple printed pie and bar labels well.

Therefore: **do not remove RapidOCR, geometry/OpenCV or deterministic validation wholesale**, but do not assume the current combined code is automatically more accurate. Qwen3-VL should be allowed to propose structured readings on pages where it succeeds; a source-backed verifier should accept or reject them. Existing full-pipeline page 3, 9, 12 and 16 rules need repairs, because they currently lose meaning that the model sees.

This is **not** a blind production accuracy claim or a proof of universal model superiority. One development PDF, 65 deliberately selected anchors and two different JSON contracts cannot settle the architecture for unseen documents.

## Experiment design

The meeting transcript was used as context, **not as an instruction to the benchmark runner**. The test addresses Rahul's request around 12:58:30-13:04:00 to try vision in isolation, define the final output, and measure speed and quality; it also respects his warning around 13:08:14-13:08:51 that a model should not certify its own extraction. The reference checks below were assembled from rendered-page visual inspection, not from asking Qwen to judge Qwen.

| Condition | Image-only Qwen3-VL | Complete pipeline |
| --- | --- | --- |
| Source/pages | Same preserved Coulton overview PDF, SHA-256 `cf569a8b25fcd36301b34e0e976e88227faa9f9cdc7804f34eddad09e8d477ad`; all 16 pages attempted | Same PDF; all 16 pages completed in saved 0.7.0 run |
| Vision model | Local Ollama `dealsynq-qwen3-vl:4b-instruct-16k`, model digest `f54051242e42352416633551e24f6dbe8ef2d96ad29630e138d382ab667235f5`, Qwen3-VL 4.4B Q4_K_M, 16,384 context, temperature 0, thinking off, maximum 8,192 output tokens | Same model tag, mandatory later semantic stage on table/chart/map paths; image regions/crops and OCR/geometry evidence supplied |
| Model input | One full 300-DPI rendered PNG per page + one generic task/schema instruction and page-number metadata. **No OCR transcript, PDF text/object coordinates, OpenCV arrays, map atlas, prior result, or answer key.** | Per-page PDF inspection, native text and table parsing when usable, RapidOCR/PP-OCRv6, OpenCV/PDF vectors, US-state reference registration when appropriate, Qwen semantic review, Python reconstruction/validation |
| Output | One lightweight semantic-page JSON per call; no automated evidence IDs or reliable source coordinates | Immutable `source-blocks/page-NNN.json` pages, document manifest, 16 inspection files, OCR/vision diagnostics, source/evidence hashes |
| Scoring endpoint | **Same selected content/ownership checks** projected from each output; not JSON-key overlap | Same checks |

The image-only side used the complete run's rendered pages only as images. Those PNGs were originally produced by Poppler; no extracted content was leaked to the Qwen prompt. This tests *vision-only extraction after generic rendering*, not whether a vision model can ingest a raw PDF byte stream without a renderer. The full run had just completed on the same host before this experiment and was not regenerated. Its page 6 took the usable-native-table branch, **not PaddleOCR**, so this comparison does not benchmark scanned tables or prove the unimplemented Paddle fallback.

The [frozen checks](reference.json) cover 18 owned cells on page 6, all 10 pie categories on page 7, 10 state/value pairs on page 8, five amount/percent pie pairs on page 9, four KPI readings on page 3, six numeric comparison claims on page 10, six scatter/text-safety checks on page 12, and six legal/column-order checks on page 16. They are heterogeneous and intentionally weighted toward known difficult regions. Their reference was visibly checked on rendered pages but created during development with access to previous pipeline outputs and a model pilot; it is **not independent, blinded human gold**. Exact matches require the right owner, not merely a number anywhere on the page. [Scoring code](score.py) and each anchor-level pass/fail are published.

Additional **agreement, not independent truth**: image-only and full output contain the same 10/10 annual-IRR bar pairs on page 11, 10/10 two-series senior-unit bar pairs on page 13, and 23/23 quarterly-yield bar pairs on page 14. The newer model is strong on visible printed bar labels. Page 13 still has an orphan `floor.` in the full text extraction; this agreement covers chart values only.

Page 6's broader comparison found **72/84** full-run data cells agreeing with Qwen on both value and column. The other **12** are genuine blank/owner differences, not `$` spacing differences: for example, the image-only model places `$28,045,777` under `Leverage (CCC Debt)` instead of `Non-controlling Interest`, and moves `$27,598,623` into that non-controlling column instead of `Coulton Creek Equity`. Visual inspection of the loan rows supports the full run's column placement. Qwen can read the tokens and still misplace the facts.

Page 8's broader comparison is worse: the image-only response misclassifies the map parent as a `chart` and emits **50** map-like rows for **27** full-run bindings. Only **7/50** assignments agree exactly with the full run; **35 rows repeat “New York”**, generally copying `1.3%`. A parseable, schema-conforming JSON file can therefore be deeply wrong. Full map reference/leader-line ownership was registered at silhouette IoU `0.97217`, though its Qwen conflicts and all source-backed values still deserve human sampling.

## Completion and speed

The first fixed-prompt image-only pass attempted 16/16 pages and produced **15/16 parseable, lite-schema-valid page JSONs**. Page 5 ran into a repeated photograph-description loop and ended in an unterminated JSON string. A second call with the same temperature-zero prompt failed the same way; the [raw retry](../../benchmarks/qwen3vl-vision-only-coulton-20260915-r3/retry-page005/page-005.raw.txt) is preserved. The full pipeline produced **16/16 complete page files**, and independent full-schema/integrity validation passed 149 blocks with zero errors (although semantic defects remain).

Recorded image-only wall time was **609.4 seconds (10.2 minutes)** for the 16 first attempts, including the failed 155.5-second page 5 and 128.4-second page 6. The saved full run took **254.5 seconds (4.2 minutes)** for all stages, about **2.39x faster** in these sessions. The extra 154.7-second page-5 retry is *not* in that image-only total. Timing is illustrative rather than controlled: runs were in separate sessions, not randomized hardware/thermal trials, and the Qwen-only side used full pages while the pipeline used region crops.

An exploratory stronger anti-repetition/one-map-label prompt was [partially recorded](../../benchmarks/qwen3vl-vision-only-coulton-20260915-r4/README.md), but page 2 and page 4 also produced unterminated repeat-loop JSON, so it was stopped before all 16 pages and **not substituted into the primary score**. This shows generic prompt tuning alone did not reliably solve completion. It is a development observation, not a measured final r4 accuracy figure.

## What to keep, what to change

1. Keep **native text/RapidOCR as the literal channel** and **geometry/PDF objects/OpenCV as source ownership** when cell positions, map regions, wedges or plotted marks matter. OCR-only lines are not a table grid, and a Qwen guess is not a verified map owner. Scanned-table/Paddle structure is still missing and needs its own test.
2. Use **current Qwen3-VL as a serious candidate extractor**, not only a low-confidence fallback. Pages 3, 7, 9, 10, 11, 13, 14 and 16 show meaningful model-only strengths. Feed its chart/KPI/column hypotheses into a verifier; do not silently discard a source-backed model reading merely because an older heuristic produced JSON.
3. Fix the complete pipeline's **page 3 KPI cluster ownership, page 9 multi-pie hierarchy, page 12 axis/data separation, and page 16 column reading order**. Its structural validation currently misses misleading content. Qwen-only should not certify its own output: compare candidates with native/OCR tokens, geometry and human-checked reference examples.
4. Keep **review flags and fail-closed behavior**. Vision-only needs bounded outputs, repeat/truncation checks, duplicate-owner checks, and unsupported-value detection. A model-only production path would still need rendering, page metadata, evidence coordinates, hashing, JSON-schema validation and a reference ledger—the “whole pipeline” does not disappear just because the extractor changes.
5. Before dropping a specialist, create a **blind, multi-document benchmark** with unrelated companies, scanned tables, mixed column layouts, multi-pie charts and non-US maps. Human reviewers should freeze exact owner/value references *before* any candidate run. Report exact cell/label accuracy, false positives, completeness, output validity, runtime and artifact provenance separately rather than one pooled percentage.

## Historical-model correction and reproducibility

The [older brief](../../output/pdf/dealsynq_vision_vs_ocr_ablation.pdf) used **Qwen3.5:4B/9B** and stricter complete-fact records on a few pages; it explicitly did **not** test current Qwen3-VL image-only over the full PDF. Its page-6 `0/61` strict fact results must **not** be compared numerically to this benchmark's `16/18` owned-cell anchors; the model, prompt, schema and scoring endpoint differ. This report is the requested current-model test and supersedes any blanket statement that “vision alone fails.”

Re-run the image-only baseline on the published full-run page images (local Ollama model and Python extras required):

```powershell
python reports/vision-ablation-qwen3vl/run_vision_only.py `
  --images examples/coulton-creek-v070-full-qwen-audited-r1/page-images `
  --output benchmarks/my-new-qwen3vl-image-only-run --pages 1-16 `
  --model dealsynq-qwen3-vl:4b-instruct-16k --prompt-profile baseline
python reports/vision-ablation-qwen3vl/score.py `
  --reference reports/vision-ablation-qwen3vl/reference.json `
  --vision benchmarks/my-new-qwen3vl-image-only-run `
  --full examples/coulton-creek-v070-full-qwen-audited-r1/source-blocks `
  --output benchmarks/my-new-qwen3vl-image-only-run/score.json
```

The benchmark artifacts retain each successful page's parsed JSON, model text and timing/usage receipt, plus failure receipts and a second raw failure response. They do not include API tokens. The original source and complete OCR/OpenCV/Qwen run remain in the linked example, so the benchmark does not duplicate its PDF or images.
